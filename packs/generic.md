# Generic capability lens

Use this lens when no specialized pack fits, or for shared components in a mixed repository. It is a fallback for supported local source, not a claim of universal language semantics.

Identify public entry points, configuration selection, principal transformations, important types/contracts, external boundaries, tests, and output handling. Trace a representative input to its declared result. Describe utilities by their actual consumers where those links can be established.

Ask where behavior is selected: direct calls, configuration, registry keys, annotations, file discovery, dependency injection, or runtime values. Dynamic connections need explicit uncertainty. An import establishes a dependency candidate; it does not establish every possible execution path.

Infrastructure definitions describe declared resources and relationships. Do not report them as deployed state. Build and CI files describe configured steps; do not claim the steps have passed. Tests describe asserted expectations; inspect assertions before claiming coverage.

For novel frameworks, preserve useful file facts and unresolved relationships. Explain which missing extraction capability would improve analysis. Do not write or execute a new parser during a vault run.
